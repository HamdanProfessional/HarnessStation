How a genuinely big feature landed behind the shim seam.

Four calls, everything else built on them

The serial-byte watcher pattern

Turning a byte stream into a promise

function onSerialByte(byte) {
  serialBuffer += String.fromCharCode(byte);
  for (const w of watchers) if (w.test(serialBuffer)) w.resolve();
}

Routing

One command name, two implementations

registerCommand("run_command", async (args) => {
  if (vmEnabled()) {
    try { return await vmRunCommand(...); }
    catch (e) { /* fall back to the shell */ }
  }
  return shellRun(...);
});

The actual commit sequence

Three commits, not one big one

1  VM: a shell for the terminal tool, over the OPFS workspace
2  Real Linux in the browser via v86 (milestone 1: boot + run)
3  VM milestone 2: wire real Linux into run_command
   with a shared filesystem

The lesson

Land the risky part in isolation first

  • Each commit was independently useful, not a fragment of one big change
  • The riskiest unknown — does v86 boot reliably — got proven before anything depended on it
