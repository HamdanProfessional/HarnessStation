Why one React tree runs on both desktop and web

The same src/ tree, two different bottoms.

Recap from E54

Five imports are the whole seam

@tauri-apps/api/core        invoke()
@tauri-apps/plugin-fs       files
@tauri-apps/plugin-http     fetch()
@tauri-apps/api/event       listen/emit
@tauri-apps/plugin-opener   openUrl/openPath
@tauri-apps/plugin-updater  check/relaunch

web/shims/ — one file per import

Same names, browser bodies

core.ts      invoke() dispatcher
fs.ts        OPFS
http.ts      native fetch (CORS applies)
event.ts     local bus, never fires cross-process
opener.ts    window.open()
updater.ts   reports no update; reload is the update
secret.ts    localStorage, labeled weaker

core.ts is a router

invoke() looks a name up in a map

const handlers: Record<string, Handler> = { … };

export async function invoke(cmd, args) {
  const handler = handlers[cmd];
  if (handler) return handler(args);
  throw new Error(UNAVAILABLE[cmd] ?? `"${cmd}" isn't available in the web version.`);
}

How a command gets a browser body

registerCommand() — no app code touched

// secret.ts
registerCommand("secret_set", (args) => {
  const { id, value } = args;
  localStorage.setItem(PREFIX + id, value);
});

The trick, stated plainly

A capability is one new shim file

  • Import registerCommand, call it for each command name
  • Zero changes anywhere in src/ — it was already calling invoke("that_name")

Gotcha

Some commands fail on purpose

  • UNAVAILABLE lists commands that are genuinely impossible in a tab — start_server, mcp_connect, mesh_start, inapp_open — each with a specific reason, not a generic error
