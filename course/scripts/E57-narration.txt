# Slide 1
Python now runs without a server. It still needs somewhere to read and write files, and a terminal to drive it from. This episode is the sandboxed workspace underneath both, and the small shell built on top of it.

# Slide 2
On desktop the file tools work against a real directory you pick on disk. A browser has no disk to point at — so vfs dot ts gives the model a workspace inside the Origin Private File System instead: real files, persisted by the browser, that survive a reload and that every tool shares.

# Slide 3
Every path the model gives a tool gets resolved against that one workspace root, and any dot-dot that would climb above it is simply dropped rather than followed. There's no way to spell a path that reaches the app's own storage or anywhere else in OPFS — the sandbox is enforced in the path resolver itself, not by convention.

# Slide 4
On top of that sits shell dot ts — a coreutils subset, not a full shell. ls, cat, echo, grep, head, tail, mkdir, rm and friends, all operating on that same OPFS workspace. Pipes chain them together, redirection writes a result to a file, and semicolon or double-ampersand sequence several commands in one call.

# Slide 5
This is the default terminal in the web build, so let's use it like one. List and filter with a pipe, chain a follow-up with double-ampersand so it only runs on success, change directory, then redirect some output into a new file — all against files that are still sitting there next time you reload the tab.

# Slide 6
It's deliberately a subset, not real bash. A command it doesn't recognize returns command not found with exit code 127 and points at the file tools or Python instead of silently pretending to understand — so a script written for a real terminal may need the file or Python tools to finish the job.

# Slide 7
A sandboxed workspace and a shell over it — but still not a real operating system. Next episode goes all the way: an actual Linux kernel, booted inside the tab.
