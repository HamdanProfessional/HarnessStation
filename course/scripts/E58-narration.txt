# Slide 1
Module 14 saves its flagship demo for last: an actual Linux kernel, booted from inside a browser tab, with a filesystem the model genuinely shares. Let's turn it on and see what it really is.

# Slide 2
It's off by default. In Settings, there's a toggle for the real-Linux terminal. Flip it on, and from then on run_command routes there instead of the coreutils shell shim we saw back in episode fifty-seven — the model is now talking to an actual guest OS.

# Slide 3
What's actually booting: Buildroot and BusyBox, running under v86 — an open-source x86-to-WebAssembly emulator — driven over its serial console. That means real uname, real busybox grep, real arbitrary guest programs. Not a JavaScript re-implementation of Unix — genuine Linux, emulated down to the instruction.

# Slide 4
Why v86 and not the faster alternative, CheerpX? Licensing. v86 is BSD-licensed and free for commercial use. CheerpX is proprietary and would mean billing every user of this feature. Slower but free beats fast but metered, for a tool meant to ship to everyone.

# Slide 5
The part worth lingering on: the 9p filesystem bridge. The guest mounts the shared tree at /mnt, and the model's OPFS workspace lives under /mnt/workspace. So a file the file tools wrote and a file a Linux command creates aren't synced copies — they're literally the same file, seen from two sides at once.

# Slide 6
State the costs plainly: about a ten megabyte one-time kernel download, a few seconds to boot, and emulated execution that's slower than native. It's headless and serial-only — there's no GUI here, no windows, just a terminal talking to a kernel.

# Slide 7
Gotcha: this is a genuinely experimental, look-what's-possible demo, not a daily driver. Expect roughly a forty second boot, and a thirty second timeout on each command — plan your demos, and your expectations, around that.
