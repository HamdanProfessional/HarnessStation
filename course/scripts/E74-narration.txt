# Slide 1
The last episode. We close the developer track, and the whole series, by looking at the project's own planning documents — where it started, what actually shipped, and what's genuinely still open.

# Slide 2
docs/PLAN.md is the original master plan — phase 1, a very simple chat app over any endpoint, deliberately excluding local hosting, MCP, attachments, RAG, projects, multi-window. Phase 2 was LM Studio-style local model hosting. Phase 3 was server mode and Claude Desktop-style extras. Reading it now, next to the app you've spent seventy-three episodes in, is the point of this slide.

# Slide 3
Now, versus then. Everything explicitly deferred in phase 1 — projects, knowledge RAG, MCP — shipped anyway, along with a great deal the original plan never mentioned at all: voice and 3D avatars, the device mesh, swarms, the entire browser build with its in-tab Linux VM, evals, benchmarks. The plan was a starting point, not a ceiling.

# Slide 4
docs/roadmap.md tracks what's current. Its Shipped table is long — nearly everything in this series is on it. What's left sits in two tiers: Tier 1 is release readiness, needing secrets rather than code; Tier 2 is real feature work, like better avatar lip-sync and semantic search across all chat history.

# Slide 5
And the single most-referenced open item across the whole doc set, in both roadmap.md and release.md, is code-signing. The installer isn't signed with a real certificate yet — that's exactly why E02 had you click through Windows SmartScreen. It's not a technical gap; the pipeline is wired and waiting, it's purely a procurement step: buy a certificate, set two repository secrets, and every future install stops tripping SmartScreen.

# Slide 6
Two companion documents are worth reading on your own time if you want to understand why the app's shape is what it is: lm-studio-plan.md, on how local model hosting actually works under the hood, and claude-desktop-plan.md, on the instruction-layering design from E11 and E27 and where it was borrowed from.

# Slide 7
If you're going to contribute, the pattern across every developer episode in this module holds: read the existing tests before writing code, keep side effects thin and pure logic tested — E71 — and land big features as a sequence of small, independently useful commits — E69. That's genuinely how this codebase grew.

# Slide 8
The end. Nineteen modules, seventy-four episodes, from installing on Windows through booting Linux in a browser tab to reading the code itself — thank you for watching the whole way. Go build something with it.
