# Slide 1
A bigger claim than the last episode: real Python, the actual language, running inside the browser tab, executing a genuine Python tool with no server anywhere in the loop.

# Slide 2
The desktop app runs Python tools by shelling out to the system Python on your PATH. A browser tab can't shell out to anything — so pyodide dot ts swaps in Pyodide: an actual build of CPython, compiled to WebAssembly, that runs entirely inside the page.

# Slide 3
It isn't bundled with the app. The first time any Python tool actually runs, pyodide dot ts pulls the runtime from the official CDN — a few megabytes, once, cached after that. Every other user of the web build who never touches a Python tool pays nothing extra.

# Slide 4
The contract matches the desktop's python underscore run exactly: run the tool's code, call the named function with the JSON arguments, hand back json dot dumps of the result. Same shape in, same shape out — so nothing above this layer, the tool editor or the model, has to know which one it's talking to.

# Slide 5
Let's reuse the tool from episode 24 — the one that calls a currency API with urllib. Same code, same save-and-test flow, but this time it's Pyodide underneath. Watch it run: real network fetch for the API, but no round-trip to any Python process on this machine, because there isn't one.

# Slide 6
Same gotcha as desktop's schema auto-detection, ported over: pyodide dot ts also reimplements python underscore schema, inferring parameters from the function's signature and docstring inside Pyodide itself. Convenient, still worth checking — a wrong inferred type still means the model calls with the wrong shape of argument.

# Slide 7
Python now runs with no server. Files still need somewhere to live, and a terminal to work in — next up, the sandboxed workspace and the shell built on top of it.
