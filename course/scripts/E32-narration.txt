# Slide 1
One agent handles one job well. But some jobs are actually several independent jobs at once — that's what swarms are for. Let's see when that's worth it, and when it's just an expensive way to go slower.

# Slide 2
Turn on Swarm and, instead of one agent working through a job step by step, several agents run at the same time, each on their own slice of it.

# Slide 3
The distinction that decides whether it helps: genuinely parallel work, like reviewing twelve independent files at once, is exactly what a swarm speeds up. Sequential work, where step two needs step one's answer, gets no benefit — a swarm there is just slower and more expensive than one agent working through it in order.

# Slide 4
While a swarm runs, a shared view shows exactly which file each agent is touching right now, so nothing gets edited twice by accident. And if one agent changes a file another depends on, that second agent is explicitly told about the change before it continues.

# Slide 5
The gotcha, and it's a cost one: several agents means several conversations billed at the same time, not one. A twelve-file swarm can be twelve concurrent runs. That's fine when the job is genuinely parallel and time matters — but it is not a default choice, and it's not free just because it's faster.

# Slide 6
Agents and swarms handle work. But some things aren't work at all — they're reference material the model should only load when it's actually relevant. That's skills, next.
