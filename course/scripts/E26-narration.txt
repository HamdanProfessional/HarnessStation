# Slide 1
Module 8 is about projects — the feature that stops unrelated work from bleeding into each other. In this one we create a project and see exactly what it isolates.

# Slide 2
A project is a container with its own instructions, its own knowledge bases, and its own enabled tools. Any chat you start inside it inherits all three automatically. Nothing about it leaks to chats outside the project, and nothing outside leaks in.

# Slide 3
To create one, click the plus beside Projects in the sidebar and give it a name. You land on three tabs — Instructions, Knowledge, and Tools — and whatever you set there applies to every chat you start inside this project.

# Slide 4
The worked example: two client projects, Acme and Brightside. Each gets its own instruction — house style, contact names, pricing — and its own knowledge base of that client's documents. They never mix, even though you're using the same app, the same day, back to back.

# Slide 5
Start a chat inside Acme and it automatically has Acme's instructions and knowledge, no setup needed. Start a plain chat outside any project and ask about Acme — it sees neither the instructions nor the knowledge. That boundary is the whole point.

# Slide 6
The gotcha: deleting a project does not delete its chats. They don't vanish — they return to your ungrouped chat list, still fully readable. What actually gets deleted is the project's memory: the accumulated facts it had learned. Keep that in mind before you clean one up.
