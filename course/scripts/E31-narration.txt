# Slide 1
An agent doesn't only run from its own panel. It can be called mid-conversation, handed a subtask, and hand back just the result. Let's see that, and the memory it keeps between runs.

# Slide 2
First, turn on the Agents tool group inside a chat. That's what lets the model in this conversation reach out and call one of your saved agents as a tool, instead of doing the work itself.

# Slide 3
Ask the chat to have the code-reviewer agent look at a specific file. It hands off the subtask, the agent runs its full spec, and only the result comes back — you see a tool-call card, not the agent's internal back-and-forth.

# Slide 4
Notice what's not in the main conversation: the agent's own tool calls, its reasoning, any files it opened along the way. All of that stays inside the delegated run. Your chat only sees the finished output — which keeps the main conversation short and readable.

# Slide 5
Each agent also keeps its own memory, separate from chat, project, or global memory. Run the code-reviewer twenty times and it accumulates what it's specifically learned about this codebase's conventions — that memory travels with the agent, not with any one conversation.

# Slide 6
A checklist for writing an agent worth delegating to: be specific about its scope, say exactly what output format you want back, give it the minimum tools it actually needs, and tell it what to do when it gets stuck instead of leaving it to guess.
