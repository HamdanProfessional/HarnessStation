# Slide 1
Track C, Advanced. We start with the question that decides everything else about running local: which model size actually fits the machine you already own.

# Slide 2
A realistic sizing table, four-bit quantized: eight gigabytes of RAM gets you a three-to-four billion parameter model. Sixteen gigabytes, seven-to-eight billion. Thirty-two gigabytes, fourteen billion. Sixty-four gigabytes and up, thirty-two to seventy billion. Bigger RAM buys bigger models, roughly linearly.

# Slide 3
But the size that matters more than raw parameter count is tool-calling reliability. A small model can write fine prose and still fail to call a tool correctly — and this app is built around tools. Prose quality is the wrong thing to optimize first.

# Slide 4
Test this early, with the same prompt from Episode 9 — read the README in this folder and tell me what the project does, with the Files tool on. If a candidate model can't complete that reliably, its parameter count does not matter.

# Slide 5
You are not choosing one model for everything. Mix local and cloud per chat: local for everyday, private work where a smaller model is plenty; cloud for the hard reasoning tasks where quality matters more than privacy or cost.

# Slide 6
Gotcha: there is a real quality gap between a quantized local model and a frontier cloud one. Set that expectation before recording anything else in this module — local is genuinely capable, not a drop-in replacement for everything.
