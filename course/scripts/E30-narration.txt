# Slide 1
Module 10 is agents, skills, and workflows — the tools for packaging your own setup so you don't rebuild it by hand every time. First up: creating an agent.

# Slide 2
Automation, Agents, New agent. Six fields make up an agent: a name, its instructions, which model runs it, which tools it can use, which knowledge bases it can search, and a working directory. Set them once, and every run reuses the same package.

# Slide 3
Here's the difference that decides whether an agent is actually useful. Instructions that say You review code produce vague, generic output every time. A real spec — what to check, what severity levels mean, what format to reply in — produces a review you can actually act on.

# Slide 4
The worked example: a code-reviewer agent. Its instructions name exactly what to check — bugs, security issues, style — rate each finding Blocking, Minor, or Nit, and reply as a bulleted list grouped by file. Give it read access to the repo and nothing else it doesn't need.

# Slide 5
Once it's saved, run it straight from the Agents panel — no chat required. Point it at a file or folder, and it works through your spec exactly the same way every time, because the instructions never drift between runs.
