Writing a new browser shim from scratch

One command, implemented on both sides, hands-on.

The target

get_clipboard_text

Small on purpose — the goal is to see the whole seam, not the feature.

Step 1 — the Rust command

#[tauri::command] in lib.rs

#[tauri::command]
fn get_clipboard_text(app: AppHandle) -> Result<String, String> {
    app.clipboard().read_text().map_err(|e| e.to_string())
}
      // don't forget:
.invoke_handler(tauri::generate_handler![
    get_clipboard_text, local::hw_info, …
])

Step 2 — the browser shim

registerCommand() in a new file

// web/shims/clipboard.ts
import { registerCommand } from "./core";

registerCommand("get_clipboard_text", async () => {
  return navigator.clipboard.readText();
});

Gotcha

A shim file must be imported to register

  • registerCommand only runs if the module is loaded — import it for its side effect, next to the other web/shims imports

The call site

Identical on both builds

const text = await invoke<string>("get_clipboard_text");

Prove it both ways

tauri dev, then web:dev

npm run tauri dev   → real OS clipboard
npm run web:dev     → browser clipboard API
      same call site, both times
