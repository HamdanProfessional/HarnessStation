**Narration:** src/lib/store.ts is a single Zustand store: one flat object of state — chats, settings, agents, the current view — plus every action that mutates it. Components never mutate state directly; they call an action, and the store decides what changes and what re-renders.

## Slide 4 · ~11s

**Narration:** Two are worth a close look. rewindTo deletes a message and everything after it, but snapshots the chat first, so it's reversible. deleteItem removes one item — a message, its reasoning, or a single tool call — to trim context, and repairs tool-call pairing at send time so a dangling tool result never gets sent to the model.

## Slide 5 · ~11s

**Narration:** Now the consumer side. ChatWindow.tsx doesn't own any chat logic — it destructures the actions it needs straight off useStore, and every button just calls one. The component's job is rendering and wiring clicks; the store's job is deciding what happens.

**On screen / action:** SWITCH TO EDITOR: open src/components/ChatWindow.tsx around line 171 — the useStore() destructure.

## Slide 6 · ~11s

**Narration:** The gotcha: two ways to patch a chat, and they're not interchangeable. updateChat patches whatever chat is currently on screen. Streaming must use updateChatById with an explicit id instead, because the user can switch chats mid-reply — patching “the current chat” would land the next token in the wrong conversation.
