## Slide 1 · ~7s

**Narration:** Memory came up briefly back in Module 9. Now the full picture — three scopes, how facts get in, and the budget that stops memory from crowding out the conversation itself.

## Slide 2 · ~11s

**Narration:** Three scopes. Chat memory belongs to one conversation. Project memory is shared by every chat inside that project. Global memory follows you everywhere, in every chat and project. Same mechanism, three different reach.

## Slide 3 · ~10s

**Narration:** Facts get in two ways. Passively, the app quietly extracts them from what you say — that is the toggle in Settings, Memory. Or deliberately, when you say “remember that” and mean it literally. Both land in the same store.

## Slide 4 · ~11s

**Narration:** Settings, Memory lists every fact by scope. Delete a wrong one directly. And Tidy merges near-duplicates — the same fact saved three slightly different ways collapses back into one, which matters once the budget comes in.

**On screen / action:** APP: Settings › Memory — list facts by scope, delete one, run Tidy.

## Slide 5 · ~13s

**Narration:** The budget: memory is allowed twenty percent of the context window by default, twenty-five percent at the most, and that ceiling is hard-capped by design — it cannot be raised past it. The consequence: a smaller model recalls less, not because it forgets more, but because the budget is a share of a smaller window.

## Slide 6 · ~11s

**Narration:** Gotcha: memory is not knowledge. A style preference — “always answer in bullet points” — is memory. A two-hundred-page spec is knowledge, and belongs in a knowledge base, not memory. Drop a whole document into memory and it can blow the entire budget on one file.

**Narration:** Memory keeps facts across chats. Next we look at chats themselves — folders, snapshots, branching, and how compaction keeps a long history usable.
