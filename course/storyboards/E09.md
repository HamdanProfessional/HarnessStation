# E09 · Giving it a tool

*Estimated voiceover runtime: 1m 6s. Generated from the deck — edit the deck, then re-run build-subtitles.mjs.*

## Slide 1 · ~7s

**Narration:** This is the most important episode in the whole series. We give the model a tool, and watch it go from answering questions to actually doing things on your machine. This is the moment a chat becomes an agent.

## Slide 2 · ~8s

**Narration:** Open the tools panel on the right of the chat and switch on Files. That's it — the model can now read and write files, but only where you allow, which is the next step.

**On screen / action:** SWITCH TO APP: open the tools panel on the right of the chat, toggle on the Files tool group.

## Slide 3 · ~11s

**Narration:** When prompted, set a working directory. This is a hard boundary: the model can only see and touch files inside this folder — nothing above it, nowhere else on your disk. Point it at a real project you don't mind it reading.

**On screen / action:** APP: when prompted, set a working directory to a real folder. Emphasise the folder picker.

## Slide 4 · ~9s

**Narration:** Now the prompt. Ask it: read the README in this folder and tell me what the project does. Watch what happens next.

**On screen / action:** APP: type the prompt and send. Let the model call the file tool.

## Slide 5 · ~12s

**Narration:** Here's the aha. A tool-call card appears in the conversation. You can see the call it made, the exact arguments it chose, and the result that came back — all inspectable. It decided to read the file, read it, and answered from what it found. That's the call, read, respond loop, and it's the heart of everything.

**On screen / action:** APP: point the cursor at the tool-call card — expand it to show the call name, arguments, and returned result.

## Slide 6 · ~13s

**Narration:** One crucial gotcha. Small local models often can't call tools reliably, no matter what their model card promises. If this step fails on a local model, that's almost always the reason — not a misconfiguration on your end. Before you go debugging, test the exact same prompt with a bigger model. If it works there, the small model was the problem.
