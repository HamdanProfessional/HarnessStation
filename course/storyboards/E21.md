## Slide 1 · ~6s

**Narration:** A short, practical one to close the MCP module: the three things that actually go wrong when you connect a server, and how to fix each one fast.

## Slide 2 · ~10s

**Narration:** One: the server won't start at all. Almost always the command is wrong, or the package didn't download. Run the exact command in a real terminal — you'll see the real error there, where it isn't swallowed by the app.

**On screen / action:** SWITCH TO TERMINAL: run the server's command directly to reproduce the start failure and see the real error.

## Slide 3 · ~10s

**Narration:** Two: it connects, but lists no tools. Some servers only expose their tools after they've finished initializing. The fix is almost silly but it works: disconnect and reconnect. The second connection catches the tools the first one missed.

**On screen / action:** APP: show a connected server with no tools; click Disconnect then Connect; tools appear.

## Slide 4 · ~11s

**Narration:** Three: authentication failures. For a stdio server, check the env token you set — a typo or an expired token is the usual culprit. For an http server, just redo the OAuth sign-in; tokens expire, and re-authorizing gets a fresh one. Two different fixes for the two transports.
