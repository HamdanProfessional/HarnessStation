## Slide 1 · ~7s

**Narration:** Module 17 continues with the other half of the app: the Rust backend. This episode is a tour of src-tauri/src — one file at a time, one command at a time.

## Slide 2 · ~11s

**Narration:** Every one of these files exposes functions marked #[tauri::command]. That attribute is the whole boundary: the frontend never talks to Rust directly, it calls invoke with a command name and arguments, and lib.rs's generate_handler list is the switchboard that routes it to one of these functions.

**On screen / action:** SWITCH TO EDITOR: open src-tauri/src/lib.rs, scroll to the invoke_handler![...] list.

## Slide 3 · ~13s

**Narration:** local.rs, at just under 800 lines, is the file behind Modules 1, 4, 12 and 22 all at once. hw_info detects RAM, AVX2 and an NVIDIA GPU for E49's fit indicator. download and extract_zip pull and unpack a model. fs_read, fs_write, fs_list and friends are the working-directory file tools from E09. run_command is the terminal tool. And start_server, stop_server, server_status supervise the llama-server subprocess from Module 12.

**On screen / action:** EDITOR: open src-tauri/src/local.rs — scroll past hw_info, download, extract_zip to fs_read/fs_write.

## Slide 4 · ~12s

**Narration:** mesh.rs is the largest file in the backend, close to 960 lines, because it's doing the most: mesh_start opens the network listener, mesh_arm_pairing and mesh_pair run the proof-of-knowledge handshake from Module 13, mesh_call sends a request to a paired peer, and mesh_export_peers lets you inspect what's currently trusted.

**On screen / action:** EDITOR: open src-tauri/src/mesh.rs — show the file length in the status bar (~960 lines).

## Slide 5 · ~13s

**Narration:** The rest of the surface, one command group per feature: mcp.rs connects and calls stdio MCP servers; browser.rs drives the Chrome extension while inapp_browser.rs drives the native in-app window from Module 7; audio.rs is mic capture, speech.rs is text-to-speech across four engines; oauth.rs is the MCP OAuth flow; secret.rs is three tiny functions wrapping the OS keychain; py.rs runs a Python tool's body and infers its schema.

**On screen / action:** EDITOR: quickly flip through mcp.rs, browser.rs, inapp_browser.rs, audio.rs, speech.rs, oauth.rs, secret.rs, py.rs.

## Slide 6 · ~11s

**Narration:** Notice the pattern across all of it: a command's Rust signature is the actual contract. fs_read takes a base and a path and returns a String or an error; there's no separate API spec to go stale, because the compiler enforces that the frontend's invoke call matches what's really there.

## Slide 7 · ~10s

**Narration:** Gotcha worth knowing before you add your own command: everything argument and return type here has to be JSON-serializable — Serialize and Deserialize. A raw file handle or a thread can't cross this boundary; only plain data can.
