Advanced llama-server launch flags

Squeeze real performance out of specific hardware.

Design first

Every flag is opt-in

Unset a field and nothing is emitted for it — an older llama-server build still launches cleanly.

The everyday flags

threads, flash-attn, mlock, no-mmap

--threads N      near the physical core count
--flash-attn on  near-universal speed/memory win
--mlock          pin the model in RAM, no swap
--no-mmap        load fully into RAM, skip mmap

The power move

--cpu-moe / --n-cpu-moe N

--cpu-moe        all MoE expert layers → system RAM
--n-cpu-moe N    first N expert layers → system RAM
↳ attention stays on GPU, experts sit in RAM

Auto-fit

--fit off / --fit-target

--fit off            disable llama.cpp's auto-fit
--fit-target N       memory margin (MB) per GPU when it's on

Proof, not a promise

src-tauri/src/local.rs → launch_tests

Unit tests assert an empty LaunchOpts emits zero arguments, and each flag appears only when set.

Gotcha

Flags need an engine that knows them

  • No effect from a flag? Check the llama-server build version first.
