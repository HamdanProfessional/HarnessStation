A concrete example

launch_flag_args, pulled out of start_server

fn launch_flag_args(o: &LaunchOpts) -> Vec<String> {
    // pure: reads o, returns strings, no process spawned
}
pub fn start_server(..., opts) {
    args.extend(launch_flag_args(&opts.unwrap_or_default()));
    // then, and only then, actually spawn the process
}

What the test actually proves

unset_options_emit_nothing

#[test]
fn unset_options_emit_nothing() {
    assert!(launch_flag_args(&LaunchOpts::default()).is_empty());
}

The general pattern

Extract the pure decision from the side effect

  • Side-effecting code (spawn, network, disk) stays thin and untested
  • The logic that decides what to do becomes a pure, thoroughly tested function
