Building your own eval set

Test cases from your real task, not a leaderboard.

Library › Evals

Prompt + what a good answer looks like

  • A test case = a prompt, plus a description of a good answer
  • Run against any model → each case comes back scored

Build 3–4 real cases

Include one “I don’t know”

  • Draw cases from work you actually did this week
  • One case where the honest answer is “I don’t know”

When to re-run

Any time the ground shifts

  • A new model becomes available
  • A prompt or agent instruction changes
  • A provider updates a model behind the same name
  • You are considering a cheaper model

Read results honestly

How it fails matters more than the score

  • A small gap between models is noise, not a signal
  • Look at how a case fails, not just the pass rate
  • Factor in cost and speed alongside the score

Gotcha

Small and real beats large and generic

Four cases drawn from your work outrank forty leaderboard questions for predicting fit.
