Building a multi-step workflow

Chain steps so one step's output feeds the next.

Where it lives

Automation › Workflows › New

  • A fixed sequence of steps, run in order
  • Each step gets its own tools and its own model
  • One step's output becomes the next step's input

Worked example

Weekly repo summary — three steps

1 Gather  pull commits + issues (tools)
2 Group   sort into themes
3 Write   turn themes into a summary

Run it

Read each step's output

Open every step as it completes — that's how you catch a step going wrong before it reaches the final output.

Reliability habits

Make steps predictable

  • Early steps: return the output unchanged — don't let them summarize early
  • Failure signal: if no results, reply exactly: NO DATA

Gotcha

Workflows need a known shape

  • Fixed sequence, output feeding forward → a workflow
  • Next step depends on what's discovered → a chat with tools does better
