What you plug a model into

A harness, not another chat box

You bring the model — free and local via Ollama, LM Studio or in-browser WebGPU, or a cloud model with your own key. HarnessStation gives it everything it needs to actually do work.

Tools & files

Read and write files, run commands, search the web, and drive a real browser — all inside a working directory you control.

Voice

Talk to it. Local speech-to-text and neural voices, barge-in, and 3D avatars — no server required.

Automation

Package roles as reusable agents, chain steps into workflows, and run them on a schedule while you're away.

MCP & knowledge

Connect hundreds of MCP servers and ground answers in your own documents with local or cloud embeddings.

Local models

Download a GGUF and run it with tuned llama.cpp flags, or run a small model on WebGPU right in the tab.

Community library

Import skills, agents, workflows and schedules others have made — or publish your own, free.

The three moments that make it click

See what it does

Watch the course on the docs site, or just open the web app and try it — everything below works today.

First look

It's a harness

You bring the model; the app brings tools, files, knowledge, voice and a browser. Private by default.

The “aha”

Give it a tool

Switch on Files, ask it to read your README, and watch the call → read → respond loop in an inspectable card. That's the moment a chat becomes an agent.

The showstopper

Linux in a browser tab

A real Linux kernel boots client-side via WebAssembly, sharing a filesystem with the model's tools. No server, no install.

Private by design

Your keys and data never leave your machine

This isn't a marketing line — it's how the app is built. There's nothing to log into and nothing phoning home. The only shared bits (benchmarks, the community library) go through a gateway that never sees your prompts or keys.

No account, no sign-up No telemetry No cloud sync Keys in the OS keychain Data in ~/.harnessx Open source (Apache-2.0)
